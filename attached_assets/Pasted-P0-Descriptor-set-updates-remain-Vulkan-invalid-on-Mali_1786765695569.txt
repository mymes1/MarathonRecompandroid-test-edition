P0 — Descriptor-set updates remain Vulkan-invalid on Mali despite the mutex/wait path. MarathonRecomp/gpu/video.cpp:462-478, :1075-1087, :1151-1158, :4971-4973, :5083-5084. Mali uses fixed descriptor arrays without UPDATE_AFTER_BIND, but SetTextureDescriptor() mutates one shared descriptor set while command buffers from the current frame can still reference it. WaitForGPU() only waits already-submitted fences (:3508-3532); it cannot protect a command list currently being recorded, and the render-thread caller explicitly skips the wait (:468-470). A descriptor replacement/free can therefore race recording or invalidate descriptors in an in-flight command buffer.
Fix: use per-frame descriptor sets (or descriptor-indexed immutable slots with deferred replacement), and retire old descriptor contents only after the frame fence. Do not update a shared set from loader/destruction paths. If retaining a shared set, serialize updates with frame recording and wait for both recording completion and all relevant fences.

P0 — Mali upload/render queue ordering still has a deadlock window and an unsafe submission model. MarathonRecomp/gpu/video.cpp:2383-2415, :2743-2749, :4772-4778. ExecuteCopyCommandList() waits for g_graphicsCommandListOpen == false before submitting an upload, while the render thread may be blocked in ProcUploadTexture()/unlock completion waiting on the loader or may not yet have queued Present(). The flag is also published only after commandList->begin() (:2745-2746), leaving a race where a loader sees false and submits while the render thread has begun recording.
Fix: guard command-list begin/end and copy submission with one state mutex/condition protocol; publish “recording” before begin(), and never synchronously wait from guest/loader code for a command that can only be drained after that same thread reaches Present(). Prefer one render-thread upload queue and completion fence/value, not a second command buffer submission on the aliased queue.

P0 — Resource destruction can invalidate GPU-referenced objects before deferred cleanup. MarathonRecomp/gpu/video.cpp:1029-1090, :1134-1177, :3601-3617. DestructResource() enqueues a raw GuestResource*; ProcDestructResource() puts it in g_tempResources[g_frame], but texture descriptor replacement and object destruction occur later based on frame rotation. Concurrent guest-side reuse/release can enqueue the same pointer twice or mutate it after enqueue. On Mali, the added WaitForMaliTextureUploads() does not prove graphics command-list references/fences are complete.
Fix: atomically transition resources to a destruction state, retain a reference/ownership token in the render command, and destroy only after the submitting frame fence plus upload fence complete. Make descriptor retirement part of the same deferred destruction record.

P1 — Swapchain acquire/present error handling can reuse invalid synchronization state. MarathonRecomp/gpu/video.cpp:2613-2685, :4594-4605, :4755-4765. acquireTexture() and present() return only a boolean stored in g_swapChainValid; on failure, the code still advances frame state and starts a new command list. Binary acquire/render semaphores are then reused by frame index without explicit retirement/reset semantics. Android surface loss commonly returns out-of-date/suboptimal during resume, so this can yield black frames, hangs, or semaphore reuse validation failures.
Fix: distinguish OUT_OF_DATE, SUBOPTIMAL, and fatal errors; do not submit/present or rotate the frame slot after failed acquire. Recreate the swapchain only after all uses are fenced, and associate semaphores with swapchain generation.

P1 — Backbuffer format handling is still too optimistic for Android WSI. MarathonRecomp/gpu/video.cpp:422-430, :3215-3224, :3463-3470. Android unconditionally selects R8G8B8A8_UNORM, while the actual surface format/color-space compatibility is delegated to the backend. The comment only addresses BGRA, but the code does not query/select the format returned by the swapchain. Gamma pipeline and intermediary texture are hard-coded to that format.
Fix: query supported surface formats and use the selected swapchain format consistently for RenderSwapChainDesc, intermediary texture, framebuffer, and gamma pipeline; handle SRGB/color-space variants.

P1 — Fixed Mali descriptor fallback can silently alias every exhausted texture to slot 0. MarathonRecomp/gpu/video.cpp:537-565, :4971-4973, :5083-5084. Returning TEXTURE_DESCRIPTOR_NULL_TEXTURE_2D on exhaustion is safe from an out-of-bounds write but causes arbitrary textures to render as blank and can hide a resource leak/descriptor pressure problem. More importantly, free() can recycle indices while old frames still use those descriptors (:570-580, destruction at :1075-1087).
Fix: fail allocation or use a bounded LRU with fence-delayed reuse; never recycle an index until all frame fences referencing it complete. Surface the exhaustion as a controlled loading/render error rather than silently aliasing.

P1 — Mali detection/profile state is not reset and model matching is overly broad. MarathonRecomp/gpu/video.cpp:2366-2374, :3028-3085. IsGalaxyTabA9() matches every SM-X11*, not specifically SM-X110-family models, and g_isMali is a persistent global. On device/backend recreation, stale profile state can select Mali upload/layout restrictions for a non-Mali device.
Fix: detect exact model allowlist plus GPU/vendor identity, and reset all device-specific globals before each device creation attempt.

P1 — Texture upload barrier metadata is vulnerable to stale host-side layout state. MarathonRecomp/gpu/video.cpp:3705-3743, :3755-3775, :4486-4492. texture->layout is a single unsynchronized CPU field updated by render and loader paths. Multiple queued uploads or a resource replacement can cause AddBarrier() to derive the wrong old layout, while the native texture generation check is only in ProcUploadTexture().
Fix: keep layout state exclusively on the render thread, attach upload generation/layout to each command, and emit explicit old/new transitions from the render-thread state machine.

P2 — Upload allocator alignment assumes power-of-two alignment and can overflow. MarathonRecomp/gpu/video.cpp:675-701. (offset + alignment - 1) & ~(alignment - 1) is valid only for power-of-two, nonzero alignment; callers pass runtime-derived values and 0x100/0x200, but malformed/driver-provided values can violate that assumption. offset + size is also unchecked for 64-bit overflow before the 16 MiB boundary test.
Fix: validate alignment != 0, use modulo-based checked alignment, and detect integer overflow before allocation.

P2 — ImGui accesses mutable global draw data across render-queue boundaries. MarathonRecomp/gpu/video.cpp:4562-4579, :4389-4397, :4422-4430. Present() builds ImGui data and enqueues DrawImGui; ProcDrawImGui() later dereferences ImGui::GetDrawData() rather than an immutable snapshot. Another present/input/UI update can mutate/free the draw lists before the render thread consumes them.
Fix: snapshot/copy draw commands and referenced texture handles at enqueue time, or execute ImGui recording synchronously on the owning render thread.

P2 — Descriptor-index shader portability remains risky on Mali. MarathonRecomp/gpu/video.cpp:480-495, :3240-3271, and shader declarations in MarathonRecomp/gpu/shader/hlsl/*.hlsl. The workaround removes variable-count/update-after-bind flags but still uses runtime descriptor-array indexing in embedded SPIR-V. The fixed array is initialized, which avoids null descriptors, but nonuniform indexing decorations/capability requirements are not verified against the selected Mali driver.
Fix: validate generated SPIR-V with Vulkan validation layers on Android; provide Mali-specific fixed bindings/switch-based shader variants if nonuniform descriptor indexing is not fully supported, rather than relying only on layout flags.

Prioritized audit findings (read-only; primary backend is thirdparty/plume/plume_vulkan.cpp):

HIGH — Resource/object lifetime is not GPU-safe. Destructors directly destroy buffers/images/views/pipelines/layouts/descriptors/query pools/semaphores/fences/command pools without waiting for submitted work (e.g. VulkanBuffer::~VulkanBuffer 1025-1029; VulkanTexture::~VulkanTexture 1278-1287; VulkanTextureView::~VulkanTextureView 1362-1365; VulkanCommandList::~VulkanCommandList 3111-3118; VulkanCommandFence/Semaphore destructors 3951-3977; VulkanDevice::release 4972-4983). waitForCommandFence only helps callers that explicitly use it. Android Mali can hang/crash when a still-referenced VkImage/VkBuffer/view is freed. Fix: track last-use timeline/fence per resource and defer destruction until completion; at minimum require/perform vkDeviceWaitIdle during teardown and before resource replacement, and enforce command-list/resource ownership/lifetime in API.

HIGH — Barrier state is global mutable state on resources and is updated while recording, not per command queue/submission. VulkanBuffer::barrierStages and VulkanTexture::{textureLayout,barrierStages} are read/updated at 3198-3217 and 3261-3283. Concurrent command-list recording or independent queues can race, and a barrier recorded on one queue can incorrectly claim the producer stage/layout from another queue; no synchronization or queue ownership transfer is used (src/dstQueueFamilyIndex = IGNORED, 3210-3211/3271-3272). This causes Mali flicker, stale data, layout validation failures, or GPU hangs. Fix: maintain per-subresource state in a synchronized resource-state tracker, serialize state transitions, or require explicit transitions; use release/acquire queue-family barriers for distinct families and submit dependencies.

HIGH — VulkanCommandList can be destroyed/reset/re-recorded while GPU is using it. begin() unconditionally calls vkResetCommandBuffer at 3121-3128; destructor frees it at 3111-3118; there is no in-flight fence association. Reuse must be gated by its prior submission fence. Fix: associate each command list with submission fence/timeline value and wait before reset/free; reject double-submit of a one-time command buffer.

HIGH — Device feature/extension/function loading is only partially robust. Device is created with appInfo.apiVersion = VK_API_VERSION_1_2 (5023-5029) without clamping to vkEnumerateInstanceVersion; BDA is enabled based on queried feature/extension and then only checks vkGetBufferDeviceAddress/KHR after vkCreateDevice (4428-4455). Other optional extension entry points are called unconditionally when capabilities imply support (e.g. ray tracing calls 1385, 2121, 3335; present wait 2574; sample-location paths), but there is no per-function pointer validation. On Mali/G57 configurations exposing extension strings but missing/quirky aliases this can become null calls. Fix: query instance API version, clamp requested version; resolve and validate every optional function after volkLoadDevice, gate each capability on both feature+extension+non-null PFN, and use core/KHR aliases deliberately.

HIGH — Optional extension enabled set is not feature-path consistent. All supportedOptionalExtensions are enabled (4515-4522), including descriptor indexing, scalar layout, robustness2, ray tracing support dependencies, etc., while only some features are conditionally chained (4390-4450). More importantly, ray tracing extension names are collected independently (4262-4269) but deferred-host-operations/pipeline-library dependencies and callable functions are not validated. Fix: build extension list per enabled feature/capability, validate required dependency closure, and disable ray tracing wholesale unless all required extensions, feature bits, properties, and PFNs are present.

HIGH — Mapped readback memory is never invalidated. VulkanBuffer::map ignores readRange and only calls vmaMapMemory (1031-1040); unmap flushes upload/GPU_UPLOAD only (1042-1063). READBACK/non-coherent host memory needs vmaInvalidateAllocation before CPU reads. Mali UMA/non-coherent heaps can return stale/corrupt data and trigger apparent freezes. Fix: for READBACK call vmaInvalidateAllocation (clamped/aligned range) before returning mapped pointer; honor readRange; pair flush/invalidate according to allocation coherence.

HIGH — Swapchain resize destroys old image views/swapchain without waiting for prior rendering/present, except Android surface recreation. resize calls releaseImageViews at 2586-2587, creates replacement, then destroys old swapchain at 2627-2629. present may have queued work; wait() is optional and only present-wait-enabled (2572-2575). On Android rotation/resizing this can destroy images still consumed by Mali. Fix: wait on per-frame acquire/submit fences (or vkDeviceWaitIdle as conservative fallback) before releasing views/old swapchain; handle VK_ERROR_OUT_OF_DATE_KHR/VK_SUBOPTIMAL_KHR from acquire explicitly.

MEDIUM — Present wait result is ignored and uses a fixed 100 ms timeout. VulkanSwapChain::wait 2569-2575 ignores vkWaitForPresentKHR result; timeout can leave frames outstanding while caller proceeds/recreates. Fix: check result, retry/propagate timeout, and use a frame-fence protocol rather than assuming present wait completed.

MEDIUM — Image barriers are over-broad and state tracking does not match views/subresources. Every texture barrier covers all mips/layers (3274-3279), while copy operations target individual mips/layers (3654-3658, 3668-3675); one subresource transition can incorrectly transition unrelated subresources and later use incompatible layouts. Fix: carry exact mip/layer/aspect ranges in RenderTextureBarrier and track each subresource; validate old layout against tracked state.

MEDIUM — Barrier stage/access conversion can produce invalid/insufficient dependencies. dstStageMask is derived from caller stages at 3160-3168 and access masks at 3201-3209/3264-3270; if caller supplies NONE, code substitutes MEMORY_READ|WRITE but leaves dstStageMask potentially zero, which is invalid (vkCmdPipelineBarrier 3293-3295). Fix: reject empty destination stages or map to ALL_COMMANDS; derive stage/access pairs from explicit usage, and use synchronization2 where available.

MEDIUM — Copy commands trust caller layouts and ranges without validation. copyBufferRegion/copyBuffer use raw offsets/size (3596-3608, 3701-3713); image copies use tracked layouts directly (3664, 3697, 3749) and do not verify source/destination usage, bounds, aspect compatibility, or compressed-format alignment. Invalid inputs can be accepted by desktop validation yet hard-fault/produce Mali corruption. Fix: validate bounds/format/block alignment and require explicit TRANSFER_SRC/DST layouts/barriers before recording.

MEDIUM — Pipeline layout compatibility is asserted only structurally, not against bound descriptor set layout. setDescriptorSet checks pointer/set index then binds (3925-3932), but does not verify interfaceSet->setLayout belongs to pipelineLayout->descriptorSetLayouts[setIndex]; pipeline creation/layout destruction also has no lifetime protection. Fix: validate layout identity at bind time and retain/reference layouts and descriptor sets until fence completion.

MEDIUM — Queue-family selection can silently choose family 0 when no matching family exists. pickFamilyQueue leaves familyIndex=0 if no queue matches, then marks it used (4462-4489). Mali generally exposes graphics/compute but transfer-only assumptions can fail on variants. Fix: return failure when no match, fall back intentionally to direct family, and check present support for the selected direct family.

LOW/MEDIUM — Thread safety is incomplete. Object construction is globally serialized (48-57, 4687-4764), and submit/present lock native queue (4067-4071, 2550-2553), but command recording, resource destruction, barrierStages/layout state, query results (3032-3070), swapchain textures/swapChains sets (2505-2519), and fence wait/reset (4081-4096) have no synchronization. Fix: document single-owner constraints or add per-object locks/state transitions; never concurrently wait/reset/re-submit the same fence/semaphore/command list.

LOW — VulkanDevice::isValid() tests vk != nullptr (4986-4988), relying on null-handle representation; use VK_NULL_HANDLE explicitly. Also many creation failures leave wrappers with null handles but callers continue (e.g. image view/pipeline creation), so add checked construction and fail-fast capability/resource creation paths.
